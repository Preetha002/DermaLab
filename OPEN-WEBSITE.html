PRESENTATION GUIDE

From image to report

Health monitoring and skin image processing in a browser.

Project workflow

Patient & vitals→Image upload→Preprocessing→Segmentation→Rule output→Report

What the browser calculates

The original-resolution RGB pixels supply mean intensity, sample standard deviation, histogram entropy, skewness and Pearson kurtosis. Processing images are resized to a maximum of 384 pixels, converted to grayscale and smoothed using 10 iterations of anisotropic diffusion. Otsu thresholding and the largest connected dark region produce the mask and boundary overlay.

How the original classification works

g = round(mean RGB intensity). The following rules are ported from Analysis.m; the label is not inferred by a trained medical model.

Rule (in evaluation order)Original labelOriginal subclass
g = 203 or 163Normal—
130 < g < 150MalignantSSM
150 ≤ g < 170MalignantNM
All other valuesBenignPsoriasis

Conversion notes

The image-processing visualization is a browser implementation, not a pixel-identical MATLAB toolbox port. The original svm.m contains active-contour segmentation, rather than an SVM training pipeline. Its PCA, wavelet and contour sequence is replaced by the documented browser pipeline above. Protected .p files are not executed.

The original 99.21, 99.34 and 99.49 performance values were hard-coded. This version does not present them as measured accuracy, sensitivity or specificity. It also does not provide treatment advice. Existing patient files and the original Firebase destination are not imported or contacted.

A quick presentation walkthrough

  1. Click “Load presentation demo” to fill fictional readings and select a supplied image.
  2. Run analysis and explain the four processing stages.
  3. Show the calculated image features and the brightness rule.
  4. Create a report, save it locally, and choose Print / PDF.
  5. Explain the limitation: clinically meaningful classification requires a validated model and labeled evaluation data.
